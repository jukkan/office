# 1.5 Tile context menu

## Goal
Give users a quick way to copy a tile's URL without entering edit mode. Surfaces as a right-click (desktop) / long-press (mobile) context menu on any tile.

Requested in [issue #5](https://github.com/jukkan/office/issues/5).

## Why a context menu rather than a copy button

Adding yet another hover-state button to the tile risks visual clutter — tiles already have the `+` quick-create button. A context menu is a natural pattern for this:
- Familiar UX (right-click to copy a link is standard browser behaviour)
- Works on mobile via long-press without extra UI
- Can consolidate multiple secondary actions in one place

## Menu items

| Action | Condition | Behaviour |
|--------|-----------|-----------|
| Open | always | `window.open(tile.url, '_blank')` — same as tile click |
| Copy URL | always | Write `tile.url` to clipboard; show brief "Copied!" toast |
| New [app name] | only if `createUrl` exists | `window.open(tile.createUrl, '_blank')` — same as `+` button |
| Edit tile | only in edit mode | Enters tile edit state — same as clicking tile in edit mode |

## Implementation notes

- Listen for `contextmenu` event on the tile `div`; call `e.preventDefault()` to suppress the browser's native menu
- For long-press on touch: `touchstart` sets a 500ms timer; `touchend` / `touchmove` cancels it; on expiry, show the menu
- Position the menu at the cursor/touch point, clamped to viewport edges
- Close on: clicking outside, pressing `Esc`, or any menu item being selected
- Use a portal (`ReactDOM.createPortal`) to render the menu at the `body` level so it isn't clipped by tile `overflow: hidden`
- The `+` quick-create button on hover can remain for discoverability on desktop, or be removed in favour of the context menu — open question

## Component
`src/components/TileContextMenu.tsx` — renders via portal, receives position + tile data as props

## Clipboard feedback
Use the existing `sonner` toast (already in the dependency tree) for the "Copied!" confirmation rather than a custom tooltip — keeps it consistent with any future toast usage.

## Open questions
- Should the `+` hover button be retired once the context menu exists, or kept as a faster shortcut?
- Should right-click in edit mode open the context menu or go straight to the edit form (current behaviour)?
