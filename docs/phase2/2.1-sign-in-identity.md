# 2.1 Sign-in and identity

## Goal
Optional Microsoft sign-in that unlocks the Graph-powered widgets. The app remains fully functional without signing in — sign-in is additive, never a gate.

## Auth flow
- MSAL.js `PublicClientApplication` with popup flow (redirect flow causes issues on GitHub Pages with hash routing)
- On load: attempt silent token acquisition (`acquireTokenSilent`) — if a cached account exists, restore the session without prompting
- If silent fails: show "Sign in" button, do nothing else until user clicks

## Header changes when signed in
- User avatar (from Graph `GET /me/photo/$value`) — fallback to initials avatar
- Display name
- Tenant name (from `account.tenantId` decoded or `GET /me/organization`)
- "Sign out" button — calls `msalInstance.logoutPopup()`, clears sessionStorage

## Component: `AuthProvider.tsx`
Wraps the app, exposes via context:
```ts
interface AuthContext {
  account: AccountInfo | null;
  signIn: () => Promise<void>;
  signOut: () => Promise<void>;
  getToken: (scopes: string[]) => Promise<string>;  // handles silent + interactive fallback
}
```

## UX notes
- Sign-in button in the controls bar (top right), same row as theme toggle and edit mode
- Signed-in state: replace button with avatar + name
- First-time sign-in: brief explainer tooltip — "Your data stays in your browser. Nothing is sent to any server."
- Consent screen will show app name "offi.ceo" and the scopes — keep requested scopes minimal at this step (`User.Read` only)
