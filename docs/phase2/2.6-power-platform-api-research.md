# 2.6 Power Platform app and environment discovery (research)

## Question
Can we retrieve a user's Power Platform environments and apps (canvas + model-driven) from a browser-based app with no backend, and reconstruct a useful "my apps" view?

## What's known

### Power Apps API
The Power Apps maker portal (`make.powerapps.com`) calls `api.powerapps.com` internally. This is a separate resource from Microsoft Graph.

Key endpoints (derived from browser network inspection of make.powerapps.com):
```
GET https://api.powerapps.com/providers/Microsoft.PowerApps/environments
  ?api-version=2016-11-01

GET https://api.powerapps.com/providers/Microsoft.PowerApps/apps
  ?api-version=2016-11-01
  &$filter=environment eq '{envName}'

GET https://api.powerapps.com/providers/Microsoft.PowerApps/environments/{envName}/apps
  ?api-version=2016-11-01
```

### Authentication
- Resource: `https://service.powerapps.com/`
- MSAL scope: `https://service.powerapps.com/user_impersonation`
- This is a second token request, separate from Graph — MSAL handles multiple resources cleanly

### Model-driven apps
Model-driven apps are not exposed via `api.powerapps.com` in the same way. They are Dataverse-resident (`appmodule` table). Retrieving them requires:
- Dataverse Web API: `GET https://{org}.api.crm.dynamics.com/api/data/v9.2/appmodules`
- Requires knowing the org URL per environment
- Different resource/scope: `https://{org}.dynamics.com/.default`
- This is a third token resource — doable but adds complexity per environment

## What needs to be verified (build a test page)

1. Does `api.powerapps.com/providers/Microsoft.PowerApps/environments` work in a browser SPA with MSAL token? (No backend, no proxy)
2. Does the returned environment object include the `linkedEnvironmentMetadata.instanceUrl` (org URL) needed to construct Dataverse API calls?
3. What does the canvas app object include — does it have a `webSessionId` or `appId` that constructs a direct play URL?
4. Direct play URL pattern to verify: `https://apps.powerapps.com/play/{appId}?tenantId={tenantId}`
5. Does the Power Apps API scope trigger admin consent in typical tenants, or is user consent sufficient?
6. Are there CORS restrictions on `api.powerapps.com` from a non-Microsoft origin?

## CORS risk
This is the biggest unknown. `api.powerapps.com` may not allow cross-origin requests from `offi.ceo`. If CORS blocks it, options are:
- A minimal Cloudflare Worker proxy (breaks the "no backend" principle but is free-tier)
- Fall back to the Phase 1 approach: manual environment entry with static deep links only

## Target outcome if feasible
- Widget: "My environments" — list of PP environments with name, type (Production/Sandbox/Dev), region
- Expandable: shows canvas apps with Play / Edit links, solution count, Dataverse link
- Model-driven apps: show if Dataverse API call succeeds, skip gracefully if it doesn't

## Research approach
Build a standalone `test/pp-api-test.html` (single-file, not part of the app build) that does MSAL auth + calls `api.powerapps.com` and logs the response. Run it from localhost. Answers CORS and response shape questions before writing any React code.
