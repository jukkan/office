# 3.2 Org-wide shareable configs

## Goal
IT admins can configure offi.ceo (tiles, sections, PP environments) and share the result as a single URL. Employees open the URL and get a pre-configured launcher. No server required.

## Mechanism
Config is base64-encoded JSON in the URL query string:
```
https://offi.ceo/?config=eyJ0aWxlcyI6Wy4uLl19
```

On load, if `?config=` is present:
1. Decode and validate the JSON
2. Show a prompt: "Import org config from [org name]? This will replace your current tiles."
3. On confirm: write to localStorage, remove `?config=` from URL (replace state)
4. On cancel: ignore the param, continue with existing localStorage state

## Config schema
```ts
interface ShareableConfig {
  version: 1;
  orgName?: string;           // shown in the import prompt
  tiles?: AppTile[];          // replaces main tile grid
  adminEnabled?: boolean;     // show admin section
  ppEnabled?: boolean;        // show PP section
  ppEnvironments?: PPEnvironment[];  // pre-load environments
  layout?: {
    density: "comfortable" | "compact";
  };
}
```

## Export UI
In edit mode, a new "Share config" button generates the URL and copies it to clipboard.
Optionally: QR code for mobile (can use a client-side QR lib or just the URL — QR adds complexity).

## Security notes
- The config URL contains no credentials or tokens — only tile names and URLs
- Validate that all URLs in the imported config start with `https://` before accepting
- Max config size: if base64 string exceeds ~2000 chars (safe URL length), warn the user to reduce tile count
- This is a convenience feature, not a security boundary — document clearly

## Open question
Should the import be one-time (prompt + apply) or persistent (re-apply the org config on every load, overriding user changes)? One-time is simpler and more respectful of user autonomy. Persistent requires a stored `configUrl` key and re-fetch logic.
